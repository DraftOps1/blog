今週は、RTX 4070をKubernetesに追加するつもりで作業を始めました。実際には、GPUノードをjoinする前に、既存クラスタのAPI、containerd CRI、Longhornの状態を先に直す必要がありました。

結果として、今週は以下を完了しました。

```text
- kube-vip / API VIP 復旧
- containerd 2.2.1 CRI設定修正
- worker3 NotReady復旧
- worker2 2TB SSD追加
- Longhorn degraded解消
- RTX 4070 GPUノードjoin
- NVIDIA Device Plugin導入
- GPU Podでnvidia-smi成功
```

## Added

### GPU node

RTX 4070を搭載した `k8s-gpu1` をKubernetes worker nodeとして追加しました。

```text
hostname: k8s-gpu1
role: gpu
Kubernetes: v1.31.14
containerd: 2.2.1
GPU: NVIDIA GeForce RTX 4070
```

### NVIDIA Device Plugin

NVIDIA Device Pluginを追加しました。

最初はCrashLoopBackOffしましたが、`RuntimeClass nvidia` を作成し、Device Plugin DaemonSetに `runtimeClassName: nvidia` を指定して解消しました。

最終的に、GPUノードで以下を確認しました。

```text
nvidia.com/gpu = 1
```

### worker2 2TB SSD

control-plane兼workerノードに2TB SSDを追加し、Longhorn diskとして登録しました。

```text
path: /mnt/longhorn-2tb
name: worker2-ssd-2tb
filesystem: ext4
reserved: 200GiB
```

## Fixed

### API VIP / kube-vip

GPUノードjoin前に、API VIPへ到達できないことが分かりました。

一時的に既存control-planeへVIPを載せてAPI入口を作り、その後kube-vipの正式holderを確認して手動VIPを外しました。

最終的に、以下を確認しました。

```text
API VIP:6443 OK
livez OK
readyz OK
kubectl get nodes OK
```

### containerd CRI

control-planeとworkerで、containerdのCRI pluginが壊れていました。

症状は以下です。

```text
unknown service runtime.v1.RuntimeService
```

原因は、containerd config内で `registry.mirrors` と `config_path` が競合していたことでした。

対応として、`registry.mirrors` を削除し、private registry向けの設定を `certs.d` 方式へ寄せました。

### worker3 NotReady

worker3も同じcontainerd CRI問題でNotReadyになっていました。 同じ修正を入れてReadyに戻しました。

### Longhorn degraded

Longhornにdegraded volumeが残っていました。worker2の2TB SSDを追加後、新しいdiskへreplicaがスケジュールされ、degraded表示は消えました。

## Changed

### GPU node labels

GPUノードのラベルは、古いプロジェクト名を含むものではなく、`homelab.local/*` に寄せました。

```text
homelab.local/gpu=true
homelab.local/gpu-model=rtx4070
nvidia.com/gpu.present=true
```

### GPU node taint

通常workloadがGPUノードに載らないようにしました。

```text
nvidia.com/gpu=true:NoSchedule
```

### GPU node Longhorn scheduling

GPUノードをLonghorn保存先として使わないようにしました。

```text
GPU node:
  allowScheduling: false
```

DaemonSetとしてLonghornのPodが乗ることは許容しますが、replica保存先にはしません。
