今週は、PostgreSQL lock wait fault injectionに入る前の前提を整えました。最初は「lock waitを再現する」だけのつもりでしたが、実際にはSLO v0、synthetic traffic、dashboard、PostgreSQL metricsが先に必要でした。

## Added

- SLO v0を定義
- read-only synthetic checkを作成
- blackbox exporter Probe `misskey-readonly-http` を追加
- RCA Metrics-only v0 dashboardを作成
- postgres_exporterを追加
- custom PostgreSQL RCA metricsを追加

## Metrics added

- probe_success
- probe_duration_seconds
- pg_rca_activity_by_wait_sessions
- pg_rca_lock_wait_sessions
- pg_rca_blocked_sessions
- pg_rca_sessions_sessions

## Verified

- Misskey scale: user=4、note=0、DB size=18MB
- CSV synthetic check: success_rate=100%、p95=0.0096s
- Prometheus Probe: probe_success=1
- PostgreSQL lock wait smoke test: wait_event_type=Lock
- Prometheus: lock wait中に `pg_rca_lock_wait_sessions=1`
- Post-test: lock waitが0へ戻る

## Changed

- RCA Metrics-only v0 dashboardにsynthetic panelsを追加
- RCA Metrics-only v0 dashboardにPostgreSQL panelsを追加
- baseline docsをGitOps repoへ保存

## Known issues

- Grafana sidecar reload API returns 401, although dashboard provisioning works
- postgres_exporter emits stat_replication collector errors
- logs baseline is not ready
- traces baseline is not ready
